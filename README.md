# 城市临时用工日结派单考勤保险与争议平台（零工邦）

面向城市临时用工场景（商超盘点、会展搭建、仓库分拣、餐饮帮工、保洁突击、活动安保）的全栈平台，覆盖
**发单 → 报名门禁 → 派单录取 → 四重到岗考勤 → 保险即时生效 → 作业事件 → 完工签退 → 日结结算 → 申诉裁决**
全链路，并按行业与企业沉淀岗位风险画像；另提供**企业临时取消岗位赔付**闭环：
临期取消时依据通知时间、工人赴岗位置、签到与历史取消规则生成到场/交通补贴建议，企业确认即到账、拒付进入仲裁，
败诉联动后续发单保证金倍率与发单排序，工人报名时可看到企业近期稳定性提示。

技术栈：**React 18 + TypeScript + Vite**（前端） · **NestJS 10 + TypeORM + MySQL 2 驱动**（后端） · **MySQL 8**（数据库） · **Docker Compose**（一键启动）。

## 一、一键启动（Docker Compose）

前置：安装 Docker 与 Docker Compose。

```bash
docker compose up --build
```

启动后访问：

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 前端（工人/企业/主管/客服四端合一） | http://localhost:8080 | nginx 托管 SPA 并反代 /api |
| 后端 API | http://localhost:3001/api | NestJS |
| MySQL | 127.0.0.1:3306 | root/root，库名 gig_platform |

首次启动会自动建表并写入演示种子数据（幂等，已存在则跳过）。

停止并清空数据：

```bash
docker compose down -v
```

## 二、本地开发启动（无 Docker）

### 1. 准备 MySQL 8（或兼容的 MariaDB 10.4+）

```sql
CREATE DATABASE gig_platform CHARACTER SET utf8mb4;
```

### 2. 启动后端（端口 3001，自动建表 + 种子）

```bash
cd backend
npm install
# 通过环境变量指向数据库（默认 127.0.0.1:3306 root/root gig_platform）
export DB_HOST=127.0.0.1 DB_PORT=3306 DB_USER=root DB_PASSWORD=root DB_NAME=gig_platform
npm run dev        # 开发模式（ts-node）
# 或
npm run build && npm start
```

如只需重置/执行种子：`npm run seed`（需数据库已就绪）。关闭启动种子：`SEED_ON_START=false`。

### 3. 启动前端（端口 5173，/api 已代理到 3001）

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 http://localhost:5173 。

后端环境变量（均有默认值，见 `backend/src/config.ts`）：
`PORT / DB_HOST / DB_PORT / DB_USER / DB_PASSWORD / DB_NAME / JWT_SECRET / SEED_ON_START`。

## 四、业务验证方式（推荐按此走一遍）

### 路线 A：界面操作（约 5 分钟）

1. **工人 `worker1`** 登录 → 岗位大厅 → 打开「星级酒店·餐饮帮工」可看到健康证门禁；
   用 **`worker2`** 报名该岗位会被「实名/健康证」门禁拦截。
2. `worker1` 打开「世博动漫展·展台搭建帮工」→ 勾选风险告知 → 报名。
3. **企业 `enterprise1`** → 岗位管理 → 报名与派单 → 录取（录取即生成 **PENDING 保单**，企业确认承保）。
4. **主管 `supervisor1`** → 现场工作台 → 查看动态二维码（60 秒轮换）。
5. `worker1` → 我的任务 → 任务室 → 到岗签到：
   - 点「模拟偏离签到点」或输入错误口令，会被定位/二维码拦截；
   - 正常坐标 + 人脸 + 输入主管端口令提交 → 状态变为等待主管确认；
   - 主管在现场工作台点「确认工人实际到岗」→ **四重校验通过，保险按实际到岗时间即时生效**。
6. 作业中工人依次上报：临时加班 90 分钟、额外搬运、工人受伤（主管端批准；工伤自动生成理赔调查，保险期内赔付）。可在任务内聊天留存沟通记录。
7. 工人完工签退 → 自动生成**日结明细**（有效工时/加班费/搬运补贴/餐补/迟到扣款/保费/平台服务费/预付款抵扣）→ 企业确认发放。
8. 工人对工资有异议 → 任务室「日结结算」发起申诉 → **客服 `support`** 打开工单，可查看签到轨迹、主管确认时间、现场照片、作业事件、聊天记录、保险、结算，选择 **补发 / 维持扣款 / 升级仲裁**（仲裁可再下裁决书）。
9. **高风险企业验证**：`enterprise_risky` 发一个「活动安保」岗 → 保证金自动按 **基准 400 × 3.0 倍**冻结、岗位要求**双人现场确认**（两名主管账号分别确认，同一人不能确认两次）。
10. 企业取消岗位 → 按距开工时间罚没 20%/50%/100% 保证金、保单作废、取消率计入风险画像。
11. 客服 → 风险画像：查看企业取消率（阈值 15%）、有责争议率（20%）、工伤率（10%）与六行业岗位风险沉淀；工伤理赔页可验证**事故时未生效保单不可改赔（禁止事后补录）**。

### 路线 B：企业临时取消岗位赔付（约 4 分钟）

演示岗位由种子预置，也可在任意「已录取工人」的岗位上自行复现。

1. **工人 `worker3`（王五）** → 我的任务，可看到「紧急·超市夜间盘点（开工前 25 分钟被取消）」与一笔**交通补贴 ¥30（待企业确认）**；
   进入任务室可见取消赔付测算（通知时间/工人位置/签到/历史倍率）。
2. **企业 `enterprise1`** → 取消赔付：对建议可「确认支付」（保证金立即扣划、工人收到到场/交通补贴）或「拒绝支付」（进入仲裁）。
3. **工人 `worker4`（赵六）** 的「演唱会安检安保」由高风险企业雷霆人力开工前 40 分钟取消、工人已到现场（~90m），企业已拒付；
   **客服 `support`** → 取消赔付仲裁 → 查看位置心跳轨迹、通知档位、企业历史取消 → 下达裁决：
   判企业有责则补贴从保证金扣付，并对该企业**后续发单保证金附加 +0.5 倍（封顶 +1.5）、排序罚分 +8、计入风险画像**。
4. 回到岗位大厅：雷霆人力在招岗位标注「近期取消/拒付频繁·稳定性差 / 排序已降权」；打开岗位详情可见近 10 单取消率与稳定性提示。
5. 自行复现：企业发一个「半小时后开工」的盘点岗 → 录取工人 → 工人在任务室多次「上报位置」（在途中/到场附近/已到现场）→ 企业取消岗位，
   系统按 **通知档位 × 位置档位 × 历史取消倍率** 逐人生成建议（未出发且无位置证据者不赔）。
   - 通知档位：开工前 1h 内（到场补贴=日结 50%+交通 ¥30）、1–2h（30%+¥20）、2–24h（20%+¥10）、24h 前（0）。
   - 位置档位（服务端按坐标 Haversine 判定，不信任端上）：已到现场≤300m 全额、到场附近≤1km 到场补贴半额、在途中≤30km 仅交通补贴、未出发/未知不赔。
   - 历史取消：企业此前临期取消赔付 1 次建议 ×1.2、≥3 次 ×1.5。

## 五、核心业务规则实现说明

- **岗位要素完整记录**：岗位、地点（含地理围栏坐标，300m）、时间、技能要求、健康证、服装、日结工资、保险保额/保费、迟到扣款（含宽限分钟）、结算方式、平台服务费率。
- **报名四道门禁**：实名认证 → 岗位强制健康证（有效期覆盖开工日）→ 历史评价（均分 ≥ 3.0、爽约 < 3 次）→ 风险告知勾选；任一不过给出明确原因。
- **四重考勤**：定位围栏（Haversine 距离）+ 人脸样本比对 + 现场动态二维码（SHA256 按分钟轮换，允许 ±1 分钟时钟偏差）+ 现场主管独立确认；高风险企业岗位额外要求**第二名负责人复核**，且两人不能为同一账号。
- **保险生效锚定实际到岗**：录取即生成 `PENDING` 保单（企业确认承保、岗位风险=行业风险+企业风险）；四重校验通过的瞬间由系统写入 `effectiveFrom=服务器记录的到岗时间`，事件时间全部以服务器时间为准，工人与客服均无法事后修改；未到岗发生事故 `coveredAtOccurrence=false`，客服强制不可改赔。
- **同一任务内闭环**：派单、考勤事件、作业事件（加班/调岗/早退/额外搬运/受伤/取消/工资争议）、保单、理赔、聊天、结算、评价全部挂在同一 assignment 下，任务室一页聚合。
- **日结引擎**：约定班次工资（早退按批准分钟折算）+ 审批加班费 + 额外搬运补贴 + 餐补 − 迟到/其他扣款 = 工人应发；企业应付 = 应发 + 保费 + 服务费，并按实际到岗人数平摊抵扣预付款；申诉补发后结算单置为 `ADJUSTED` 并留痕。
- **争议裁决**：工人申诉时系统固化证据快照；客服可在证据包中查看签到轨迹、主管确认、现场照片、聊天记录，做出补发、维持扣款或升级仲裁；仲裁终局裁决同样回写结算。
- **企业风险画像**：滚动统计取消率（>15%）、有责争议率（>20%）、工伤率（>10%），综合定级 1–5；L4+ 企业发单保证金倍率最高 3.0、全部岗位双人现场确认；行业维度沉淀岗位数、取消率、工伤数与“事故时未保险”件数。
- **保证金**：企业预充值 → 发单按「行业基准 ×（风险倍率 + 仲裁附加倍率）× 人数」冻结 → 完工释放 / 取消按 20%·50%·100% 罚没；取消赔付确认或仲裁判付时从冻结额优先扣划、不足扣可用余额。
- **临时取消岗位赔付**：取消时按派单逐人生成赔付单，规则 = 通知时间档位（开工前 1h/1–2h/2–24h/24h 前，对应到场补贴日结 50%/30%/20%/0 与交通 ¥30/20/10/0）× 位置档位（服务端 Haversine 判定：≤300m 已到现场全额、≤1km 到场附近到场补贴半额、≤30km 在途中仅交通、未出发/无证据不赔）× 历史取消倍率（既往临期赔付 1 次 ×1.2、≥3 次 ×1.5）；已四重签到者按已到现场顶格。企业确认 → 保证金扣划、工人补贴即时到账并留通知时间；拒付 → 进入平台仲裁，客服证据包含位置心跳轨迹/签到/通知档位/企业历史。
- **仲裁联动排序模型**：拒付败诉每岗位只计一次——后续发单保证金附加 +0.5 倍（封顶 +1.5 倍）、排序罚分 +8（确认临期取消赔付 +2）；岗位大厅按 `-(风险等级-1)*3 - 近10单取消率*20 - 罚分` 排序，稳定企业靠前；工人报名时在岗位大厅与详情看到近 10 单取消率/拒付败诉的稳定性提示（拒付败诉不受小样本保护，纯取消率需 ≥3 单才定级）。

## 六、目录结构

```
.
├── docker-compose.yml          # mysql + backend + frontend 一键启动
├── backend/                    # NestJS + TypeORM
│   ├── src/
│   │   ├── entities/           # 14 张领域表（含 worker_location_pings / cancellation_compensations）
│   │   ├── risk.constants.ts   # 行业风险/保证金/取消赔付档位/排序罚分常量
│   │   ├── seed.ts             # 幂等演示种子（含临期取消待确认与拒付仲裁案例）
│   │   └── modules/            # auth/jobs/tasks/settlements/appeals/reviews/dashboard/enterprise/risk/cancellations
│   ├── scripts/smoke-test.mjs  # 63 项端到端断言
│   └── Dockerfile
└── frontend/                   # React + Vite
    ├── src/pages/              # worker / enterprise / support 三端 + 共享任务室
    │                          # （取消赔付：EntCompensations / 客服 CompensationDesk）
    └── Dockerfile + nginx.conf
```

> 说明：本项目为全栈应用（含可直接完成业务操作的前端页面），按任务约定不再额外提供 Swagger/OpenAPI UI；
> 所有接口以 `/api` 为前缀，JWT 鉴权（`Authorization: Bearer <token>`），角色分为 WORKER / ENTERPRISE / SUPERVISOR / SUPPORT。
